# ADR-0151: The tokens live in the styles package

## Status

Accepted 2026-10-05 by the owner. It replaces the plan's P2.1, which had proposed a
private `libs/foundations`. That plan was never built, and no ADR recorded it.

## Context

The `--ui-*` tokens had their source of truth in the scaffold template,
`libs/create-workspace/src/generators/preset/files/styles/tokens.css`.
`sync-tokens.mjs` copied that file into the three framework libraries and into the
`atelier-design` skill. The docs site, in turn, imported the _React_ copy. The file
that defines the design system's foundations therefore lived inside a generator
template, and one consumer reached it through another framework's copy.

ADR-0148 then published `@atelier-ui/styles`, the class-rooted component CSS that all
three frameworks share. Every rule in it reads `var(--ui-*)`, but the package did not
ship the tokens those rules need. A consumer who used it directly had to fetch them
from a framework package.

The plan's original idea, a private `libs/foundations`, predates ADR-0148. It existed
to avoid a new release surface. That surface now exists anyway.

## Decision

1. **`libs/styles/src/tokens.css` is the one hand-edited token file.** It is published
   as `@atelier-ui/styles/tokens.css`; the package's existing `./*.css` export already
   covers that path.
2. **Every other copy is generated by `sync-tokens.mjs` and diffed by `check:tokens`.**
   The copies are:
   - `libs/{angular,react,vue}/src/styles/tokens.css`;
   - the preset template;
   - the skill asset `colors_and_type.css`.
3. **The framework packages keep publishing `styles/tokens.css`.** Existing consumer
   `@import`s keep working, and nothing breaks.
4. **The install docs recommend `@atelier-ui/styles/tokens.css`.** Angular and Vue
   consumers install `@atelier-ui/styles` first: their packages inline the component
   CSS, so they do not depend on it at runtime. React already depends on it.
5. **The scaffold still vendors its own copy.** Attendees are meant to edit it, so it
   is a generated _starting point_, not a runtime dependency.
6. **The generated copies carry no AUTO-GENERATED header.**
   - `parity-inputs.js` hashes the framework copies' bytes. A header would invalidate
     every parity record and force a Figma re-record for no gain.
   - In the scaffold copy, which attendees edit, such a banner would be false.
   - Drift protection is `check:tokens`. Its failure on an edited source was
     demonstrated, then restored.

## Why

- **The foundations belong next to what consumes them.** `@atelier-ui/styles` is the
  package whose every rule reads a token. DB UX splits the same two layers into
  `core-foundations` and `core-components`, two packages. For one design system with
  one consumer-facing CSS package, a second package would add release surface without
  separating anything a consumer installs on its own. **Rejected:** a separate
  `@atelier-ui/foundations`.
- **Rejected: a private `libs/foundations`.** It moves the source but publishes
  nothing, so the styles package would still ship rules without their tokens.
- **Rejected: dropping the framework copies.** That would break every consumer's
  existing `@import`, in exchange for removing three generated files.

## Consequences

- `@atelier-ui/styles` is self-sufficient for plain-CSS use: tokens plus component
  CSS. That is the "works without JS" layer DB UX offers. Nobody asked for it, but it
  now exists at no extra cost.
- `check:pack-styles` proves the published shape: a packed `@atelier-ui/styles`
  carries `tokens.css` byte-identical to the source, and a throwaway consumer's bundler
  resolves `@import '@atelier-ui/styles/tokens.css'` from its own `node_modules`.
- Stylelint's component rules exclude the root-level `tokens.css`, because it is raw
  literals by design. The coverage walk behind `[PARTIAL-COVERAGE]` (ADR-0149) skips it
  for the same reason.
- `git log --follow` reaches the file's older history only with copy detection
  (`-C`). The move and the regenerated preset copy landed in one commit, so every
  commit builds, which costs the pure-rename record.
- Still open, and decided separately: the three hand-written `foundation/*.mdx`
  Storybook pages (colors, spacing, typography). They are byte-identical across the
  frameworks and carry literal hex values.
