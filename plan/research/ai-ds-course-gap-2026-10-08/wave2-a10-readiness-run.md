## Per criterion

### 1. Unbound fills / strokes / spacing / radius (hardcoded values)

- Tools: `figma_lint_design` rule `hardcoded-color` (in the default `design-system` group), plus custom read-only `figma_execute`
  that walks every node outside instance internals and checks `fills[].boundVariables.color`, `strokes[].boundVariables.color`,
  `boundVariables.{paddingX,itemSpacing,cornerRadius/topLeftRadius}`.
- `figma_lint_design` returned **no `hardcoded-color` category** for any of the three (categories returned: `default-name`,
  `no-autolayout`, `no-text-style`, `empty-container`). The lint tool has no spacing or radius rule, so those need the custom walk.
- Custom walk: **0 unbound fills, 0 unbound strokes, 0 unbound radius, 0 unbound spacing on all three.**
  Positive control (so zero is not a bug in the script): Badge 20 bound fills / 30 bound strokes / 10 radius / 18 spacing
  bindings; Card 72 / 20 / 24 / 36; Dialog 45 / 15 / 15 / 30. Example: variant `55:12` fill bound to `VariableID:877:407`
  (`color/surface-sunken`), text `3:466` fill bound to `877:413`.
- Every bound variable resolves to the collection "Library Tokens" (Badge 15 variables, Card 13, Dialog 15). Component Tokens
  (15 variables) are not used by these three masters.
- Text styles: lint `no-text-style` flagged Card 12 text nodes (e.g. `3:350`, "Card body text...") and Dialog 10 (e.g. `3:529`
  "Confirm Action", `3:533`); Badge 0. My walk: Card has 24 of 36 text nodes on a text style, Dialog 10 of 20, Badge 10 of 10
  (`styles.text` `915:2345` / `911:994`). So the unstyled ones are the body/title text, which still bind font size to variables
  (`boundTextVars`: Card 12, Dialog 10). Not "hardcoded", but a gap in the strict token reading.
- NotebookLM claim ("100% token binding, 0 unbound fills before handoff"): **held as a checkable criterion; met by all three.**
  The claim that a lint tool covers it only partly holds: the MCP lint covers colour but not spacing/radius.

### 2. Variables missing `codeSyntax.WEB`

- Tools: `figma_get_variables` (`format: filtered`, `verbosity: full`) and read-only `figma_execute` over
  `figma.variables.getLocalVariablesAsync()`.
- Result: **284 of 284 local variables have empty `codeSyntax` (`{}`)**. None has `WEB`. Per collection: Library Tokens 0/141,
  Primitive Tokens 0/76, Docs Brand Tokens 0/39, Component Tokens 0/15, Effects Tokens 0/11, Motion Tokens 0/2.
  The bound variables of the three masters: **0 of 15 / 13 / 15 have `WEB`**. Example: `color/border` `VariableID:877:409`
  returns `"codeSyntax":{}`.
- What replaces it here: all 141 Library Tokens variables (and every other variable, 284/284) carry a `description`;
  the 141 Library ones read "Mirrors --ui-color-border in tokens.css (generated by tools/scripts/gen-figma-library-tokens.mjs ...)".
  So the code name is recoverable, but only as prose, not in the field `get_design_context`-style tools read.
- NotebookLM claim ("every variable must have `codeSyntax.WEB`; without it MCP tools return raw Figma names"): **checkable and
  unmet here.** Whether it matters for Atelier's own loop is untested: `figma_get_component_for_development` returns variable
  _ids_ only (`"id":"VariableID:877:407"`), never names or code names, with or without `codeSyntax`. I did not run the official
  `figma-mcp` `get_design_context` (not in scope), so "returns raw names without it" is **unverified**.

### 3. Variables with `ALL_SCOPES`

- Tool: read-only `figma_execute` (`variable.scopes`). Neither `figma_get_variables` summary nor lint reports it, but
  `figma_get_variables` with `verbosity: full` does list `scopes`.
- Result: **19 of 284 variables have `ALL_SCOPES`, all non-BOOLEAN**: Effects Tokens 11/11 (`e/0` to `e/5`, STRING), Motion Tokens 2/2
  (`m/fast`, `m/std`, STRING), Library Tokens 6/141. Primitive, Component and Docs Brand collections: 0.
  **The variables bound by the three masters: 0 with `ALL_SCOPES`**; they are scoped, e.g. `spacing/3` = `GAP`,
  `radius/full` = `CORNER_RADIUS`, `color/surface-sunken` = `FRAME_FILL, SHAPE_FILL`, `color/border` = `STROKE_COLOR`, `color/text` = `TEXT_FILL`.
- Note on the audit checklist's TA4 rule (BOOLEAN exempt): the 13 STRING variables with `ALL_SCOPES` are not covered by that exemption;
  STRING variables of motion/effect type cannot be bound to design properties anyway, so they are likely benign. Not judged further.
- NotebookLM claim: **held as a checkable criterion; the three masters pass, the file does not.**

### 6. TEXT component properties for labels

- Tools: `figma_analyze_component_set` (`componentProps`), `figma_get_component_for_development`
  (`componentPropertyDefinitions`), `figma_execute` (`componentPropertyReferences.characters` on TEXT nodes).
- Result: **0 TEXT properties on all three** (`componentProps: {}` in all three analyses). TEXT nodes bound to a property:
  Badge 0 of 10, Card 0 of 36, Dialog 0 of 20. Across the page: **10 of 43 masters have a TEXT property**
  (AtlTextarea `55:87`, AtlSelect `55:92`, AtlButton `129:20`, AtlAvatarGroup `508:7221`, AtlTooltip `55:52`, ...); 27 of 43 have a BOOLEAN; 0 have INSTANCE_SWAP or SLOT.
- Here the absence is deliberate for Badge (ADR-0067: label is children, "text inside a Figma instance is editable without a property").
  For Card and Dialog the same reasoning is not documented in the descriptions I read, and "Confirm Action" / "Card Title" are not exposed as props.
- NotebookLM claim ("bind labels to TEXT properties so overrides survive and map to props"): **checkable, but not a universal
  rule for this repo.** Atelier decided against it for children-shaped content. A readiness checklist should say "decide, and
  record why", not "always add".

### 7. Consistent layer names across variants

- Tool: no MCP tool. Custom `figma_execute` comparing the child-name sequence of each variant.
- Card: **1 distinct name signature across 12 variants** (consistent). Dialog: **1 across 5** (consistent;
  `header|Confirm Action|close|Vector|Vector|Frame|content|...|footer|Frame|Cancel|Frame|Confirm`).
- Badge: **5 distinct signatures across 10**, but split by `variant`, not by `size` (each variant value pairs 2 sizes with the same
  names): `default` = `Default`; `success` = `check|Vector|Default`; `warning` = `warning|Vector|Vector|Vector|Default`. The difference
  is the variant-specific icon instance, which is intended. The text layer is `Default` in every variant, including `success`, `danger`,
  etc. (the layer name does not follow the variant), which is the property that matters for override survival.
- `figma_analyze_component_set` supports this indirectly: `diffFromDefault` is `null` for every variant of all three, and
  `stateMachine.defaultState` is `null` (see "Tool limits").
- NotebookLM claim: **held, with the refinement that variant-specific layers legitimately differ.**

## Checklist candidate (what a docs page could say, backed by this run)

1. **Every fill, stroke, padding, gap and corner radius is bound to a variable.** Checked: lint `hardcoded-color` for colour; spacing and
   radius need a custom `figma_execute` walk (no lint rule). Result here: 0 unbound on all three masters.
2. **Bound variables are scoped, not `ALL_SCOPES`.** Checked via `figma_get_variables` (`verbosity: full`) / `figma_execute`.
   The three masters pass; the file has 19 of 284 variables on `ALL_SCOPES` (Effects 11, Motion 2, Library Tokens 6).
3. **The code name of each variable is recoverable by the agent.** Checked: `codeSyntax.WEB` is empty on 284 of 284; the code name lives in
   the variable description ("Mirrors --ui-..."). Pick one place, and say which. Whether tools surface it is **not verified**.
4. **No default layer names inside the component's own tree.** Checked: lint `default-name`. 20 real hits on Dialog (`Frame`, e.g. `3:531`);
   ignore `Vector` hits inside library icon instances. Numbered names (`card-section-2`) are not caught by the tool.
5. **The master has a structured description** (what it is, use when / don't use when, variants mapped to code props, a11y note). Checked:
   present on 43 of 43 masters, 3 of 3 read. Nothing verifies it matches the node's properties.
6. **Variant layer names are identical across variants, except where a variant owns a layer.** Not checked by any tool; custom walk only
   (Card 1 signature across 12, Dialog 1 across 5, Badge differs by variant icon only).
7. **Label and content decisions are recorded:** either a TEXT property, or a stated reason why not (here: ADR-0067, text is children).
   Checked: 0 TEXT props on all three; 10 of 43 masters have one.
8. **Accessibility scorecard run, and its classification read.** Checked: score 100 on all three, but Dialog was classed `presentational`,
   so focus and target-size checks were skipped. Treat a 100 on an overlay as "not assessed".

Could not check: Code Connect mappings; detachment rate (no tool; threshold unsourced); Dev Mode annotation quality (count was 0);
nesting depth above 1 component level; whether handoff tools show a better result when `codeSyntax.WEB` is set; the Card run of
`figma_get_component_for_development`.
