# Wave 3 / B3 — cold-start agent build test (2026-10-09)

A Sonnet agent with no access to the repo built an Angular "Account settings" page against `@atelier-ui/angular@0.3.14`, using only `llms.txt` and what it links to, the installed package, and the hosted Storybook MCP. `ng build` passed; nothing was opened in a browser. Its friction log follows verbatim. Findings were re-checked against the repo before acting on them (see `tasks/todo.md`).

## B3 live test log: building "Account settings" with Atelier UI (Angular)

Setup: Angular CLI `new --defaults --zoneless --skip-tests --ssr=false` (Angular 22.2, Node 26) into `account-app/`, `npm install @atelier-ui/angular` (0.3.14). Full `ng build` succeeded (exit 0, no warnings). Not verified: runtime rendering in a browser, a11y output, dark mode.

1. Trying: find the entry point. Source: https://atelier.pieper.io/llms.txt. Worked well: short, lists package names, version, 28 components with prop/variant unions, links to llms-full.txt, install page, Storybook. Missing: the Angular selector/class names (only "Button", "Toggle"), and no mention of the hosted MCP endpoint URL anywhere in llms.txt (I had to take it from the task brief). Resolved by going to llms-full.txt.

2. Trying: learn selectors and bindings. Source: https://atelier.pieper.io/llms-full.txt (137 KB, ~35k tokens). Worked very well: a JSX-to-Angular syntax cheatsheet, a props table per component, Angular usage snippets, `whenToUse`/`antiPatterns` metadata (e.g. Toggle vs Checkbox, Alert vs Badge). I got `atl-input [(value)]`, `atl-toggle [(checked)]`, `atl-select`/`atl-option optionValue`, `atl-card-header/-content/-footer`, `atl-alert variant`, `atl-badge` right the first time. Friction: the props tables are React-shaped (`onValueChange`, `children: ReactNode`, `onDismissed`) for all frameworks; for Angular I had to translate `onDismissed` to `(dismissed)` (guess, later confirmed in .d.ts) and ignore `children`. Size: 137 KB is heavy to paste for one page.

3. Trying: install. Sources: llms-full.txt "Quick Start" and https://atelier.pieper.io/install. llms-full says `@import '@atelier-ui/angular/styles/tokens.css'`; the install page says to use `@atelier-ui/styles/tokens.css` and that `@atelier-ui/styles` is NOT installed by the Angular package (separate npm install), while the Angular-path import "still works". Two recommended paths, contradictory-looking. I used the angular path (works, no extra package). Also the llms-full says "Angular 21+"; the package peerDependencies say `^22.0.0` (and `@angular/cdk`, `@angular/forms`). With a fresh Angular 22 app this was fine; with Angular 21 it would warn. Ambiguous version claim. The install page is an HTML page with lots of non-machine noise (inline script comments leaked into text), usable but not machine-first.

4. Trying: `npm install @atelier-ui/angular`. Worked first time, no peer-dep errors on Angular 22 (cdk was already present from the CLI template? it showed `@angular/cdk` in node_modules). Package README is minimal but correct (token import line plus one usage example); it does not list the components.

5. Trying: confirm selectors/inputs from package typings. Source: `node_modules/@atelier-ui/angular/types/atelier-ui-angular.d.ts` and `fesm2022/*.mjs` (grep `selector:`). Worked well: JSDoc on every input, selectors greppable, `AtlAlert.dismissed` output confirmed. One minor issue: the README and docs do not give a flat list of exported symbols; I had to grep for `selector:` to find `AtlCardHeader`, `AtlCardContent`, `AtlCardFooter`, `AtlOption` class names (the names are guessable from the selectors but I imported `AtlCardHeader` etc. as a guess that the compiler then confirmed).

6. Trying: hosted MCP. `curl -X POST https://atelier.pieper.io/storybook-angular/mcp` with `Accept: application/json, text/event-stream` and JSON-RPC. Worked: `tools/list` returns docs-list, docs-show, docs-show-story. Responses are SSE-framed (`event: message` / `data: {...}`), need the Accept header or it would likely fail; no auth. `docs-list` gave IDs like `components-inputs-atltoggle`. `docs-show` gave Inputs/Outputs TS types, with real Angular two-way markers (`checked?: boolean; // two-way: [(checked)]`) and `checkedChange` outputs, plus stories with runnable Angular code. This is more accurate for Angular than llms-full.txt (React-shaped). Friction: docs-list text is truncated per entry ("Usage: ```html <atl-bu...") and lists two non-components first (KitchenSinkDemoComponent, ShowcaseAllComponent); `docs-show` output is long (stories repeated); IDs need the category segment (`components-inputs-...`), not guessable from names (I would have tried `atltoggle`). llms.txt links the Storybook UIs but never the `/mcp` URLs.

7. Trying: form layout. The "form" has no `<form>` element guidance. Neither llms-full nor typings explain how to compose a labelled form with Signal Forms (`[formField]`) versus plain `[(value)]`; llms-full mentions `[formField]` only in the cheatsheet. I used `[(value)]` signals plus `(submit)` with preventDefault. Note `atl-button` is a custom element with `role="button"` and no `type="submit"` behaviour, so a click does not submit a `<form>`; I bound `(click)` on Save. This is not documented in llms-full (the AtlButton props table has no `type`). Had to read the compiled `.mjs` to discover the host is `<atl-button role="button">`. Likely a real gotcha for form-submit via Enter key (the `<form (submit)>` is only triggered by Enter in a text input if there is an implicit submit button; there is none, so Enter in the input would not submit, which I did not verify).

8. Trying: toggle label. llms-full and MCP both show label as projected content: `<atl-toggle>Email notifications</atl-toggle>`. Worked. For Input/Select, `label="..."` input. Worked. Slight inconsistency (label via content for toggle/checkbox, via input for input/select) but documented by examples.

9. Trying: select options "English/German". `atl-select` `[(value)]` + `<atl-option optionValue="en">`. Worked as documented. Note the `value` default is `''` so with no placeholder the control shows nothing; I preset `'en'`.

10. Trying: success alert after save. `atl-alert variant="success"` with `@if`. Worked. llms-full says Alert has `accessibility.role: alert`, so it is a live region; conditionally rendering it announces. Good guidance. The anti-pattern note ("transient message use toast") is helpful, and I deliberately used alert since the brief asked for it.

11. Trying: badge "Beta". `atl-badge variant="info"` (variant list default|success|warning|danger|info; no neutral "beta" or "primary" variant, so `info` is a guess about intent; `default` also valid). Metadata explicitly lists annotating with a "beta" marker, good. Note: badge is non-role, decorative; fine here.

12. Trying: styling with tokens only. Source: llms-full.txt "Design Token System" plus `node_modules/@atelier-ui/angular/src/styles/tokens.css`. FRICTION (biggest): llms-full documents `--ui-color-background` ("Page background") and `--ui-spacing-1 through --ui-spacing-12 (0.25rem steps)`. `--ui-color-background` does NOT exist in the shipped tokens.css (the page background token is `--ui-color-surface`), and spacing has gaps (no 7, 9, 11; 10, 12, 16 exist). I used `--ui-color-background` in my first draft; the Angular build passed silently (CSS `var()` of an undefined property is not an error), so a wrong token fails only at runtime (page would have an invalid-at-computed-value background, transparent). I found it only because I grepped tokens.css after the build. Fixed to `--ui-color-surface`. Also stated `--ui-font-size-xs/sm/md/lg/xl` is accurate, but shorthand tokens `--ui-type-headline/title/body-*` exist in the CSS and are not in the short list, though they appear in the "Token Annotations" section I only skimmed (the `--ui-type-*` are font shorthands usable with `font:`; I discovered this by reading tokens.css, and used `font: var(--ui-type-headline)` after confirming it's a shorthand).

13. Trying: "no raw colours" verification. grep for hex/rgb in my `src/app` and `src/styles.css`: none. There is no lint rule or helper provided for consumers (the llms-full mentions `check:token-bypass`, an internal repo gate, not available to a consumer). No machine-readable token manifest (JSON) found; only CSS and prose.

14. Trying: page title semantics. No page-level heading/layout component exists (no `atl-page`, `atl-heading`); I used a plain `<h1>` with `--ui-type-headline`. Not a defect, but llms-full gives no guidance on typography for headings outside components.

15. Trying: a11y guidance. llms-full "Accessibility Notes" is 5 generic bullets; per-component `accessibility.*` metadata is strong (role, keyboard behaviour). Missing: guidance on form-level a11y (grouping, error summary, announcing the save result, `autocomplete` attributes on name/email inputs; AtlInput has no documented `autocomplete` input, so `autocomplete="email"` can't be set on the native input, which I did not verify further).

16. Trying: build. `ng build` first attempt passed (exit 0) in about 5s; bundle 339 kB raw (82 kB transfer). No warnings. Angular CDK overlay for select did not need extra setup. Worked well.

17. Guessed (not confirmed in docs before use): `(dismissed)` output name (confirmed afterwards in .d.ts), `AtlCardHeader/Content/Footer` class names, `variant="outline"` for Cancel (documented variants: primary|secondary|outline|danger; I chose `outline` vs `secondary` with no guidance on which is the conventional "Cancel"), `variant="outlined"` for the card (documented), `--ui-color-background` (WRONG, see 12), `--ui-spacing-*` values (existed).

18. Not tested: runtime behaviour (screenshot, a11y audit), the React/Vue endpoints, `[formField]` Signal Forms, dark mode toggle, the docs pages /design-principles and /components/*.
