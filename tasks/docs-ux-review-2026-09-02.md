# Docs Site UI/UX Review — the Product Surface

**Date:** 2026-09-02 · **Scope:** the docs app as an interface (visual, interaction, a11y, responsive, motion, navigation), not the training content (`schulung-review-2026-09-02.md` covers that) · **Method:** `ui-ux-pro-max` skill checklist (§1–§9) + one static CSS audit (read-only subagent over `global.css`, `docs-theme.css`, `BaseLayout.astro`, `components/*.astro`) + one Playwright sweep of every crawlable page (58) × 4 widths (1440 / 1024 / 768 / 375) × 2 themes with probes (overflow, headings, landmarks, targets, text size, anchors) and axe-core 4.13 at 1440 + 375 (236 runs) + focus walk on 4 pages (177 stops) + drawer test at 375 + own Chrome spot-checks at 1600 · **Environment:** local HEAD (`e0dba52`) on `:4300`. Sweep scripts and raw output live in the session scratchpad (`sweep.mjs`, `summarize.mjs`, `sweep.jsonl`, `focus.jsonl`, `drawer.jsonl`).

---

## 1. Verdict

The shell is well built where it was built deliberately — skip link, theme toggle, mobile drawer focus management, search combobox, reduced-motion sweep, no-FOUC theming, containment of wide content at ≥768 px — and it falls over in the places nobody measured: **every page is 401 px wide at a 375 px viewport** (the topbar's min-content), **every TOC jump lands its heading under the 68 px sticky header** (no `scroll-padding-top`; the one `scroll-margin-top` rule targets a class no template uses), and **the home page's dark-mode CTA is white text on light teal at 1.3–1.8 : 1**. Three blockers, one cause each, each a few lines to fix.

Below that sits a consistent pattern: the docs CSS was written without the discipline the library CSS is gated on. ~40 raw colour literals, 10 ad-hoc z-index values next to an unused `--ui-z-*` scale, 11 breakpoints, 35+ selectors below 12 px, body copy at 13–14.4 px on 30 of 40 prose pages with no mobile bump, a 100ch reading column. None of it is hard; all of it is the same defect class `check:css-tokens` and `check:geometry` already catch for `libs/` — and `docs/` is outside their roster.

**Counts: 3 blockers · 13 major · 12 minor** (+ 3 component-library defects surfaced by the docs demos, routed to the library backlog).

## 3. What is good (keep)

- **Skip link** is first in DOM, visible on focus (`12,12 · 134×44`, white on primary) after a 150 ms slide; target `#main` exists. Verified by Tab + screenshot.
- **Focus indication** on all 177 tab stops sampled across 4 pages (`/`, `/tutorial`, `/components/button`, `/tokens`) — a genuine baseline ring (`--ui-focus-ring`) on every interactive class; only the two search fields defeat it (M6).
- **Theme toggle**: `aria-pressed` synced, `localStorage` + `prefers-color-scheme` fallback, no flash of wrong theme (inline head script + `astro:before-swap` copy), view-transition reveal with reduced-motion and `AbortError` fallbacks (`BaseLayout.astro:220-238, 592-660`).
- **Mobile drawer focus management**: focus moves to the close button on open, Tab stays inside, Escape closes and returns focus to the trigger, `inert` on the closed drawer, `bindOnce` guards against `ClientRouter` double-binding — measured at 375, matches the code (`BaseLayout.astro:663-762`).
- **Search** is a complete combobox (`role`, `aria-expanded/controls/activedescendant`, listbox/option, arrow keys, `aria-live` count, ⌘K) — `Search.tsx`.
- **Reduced motion**: three `prefers-reduced-motion` blocks including a `*, ::before, ::after` sweep and token zeroing (`global.css:692-707`, `docs-theme.css:144-148`); durations are token-bound (150/200/300 ms).
- **Structure**: exactly one `h1` and one `main` on every page; no `<img>` without `alt`; no `<iframe>` without `title`; landmarks present (`header`, `nav ×4`, `main`, `aside`, `footer`) with labels (see n8 for the two weak ones).
- **Containment at ≥768**: zero document-level overflow across 348 combos; `.docs-main-content { min-width:0; overflow-x:auto }` (ADR-0087) does its job — M1 is about *where* the scrollbar sits, not whether content is cut.
