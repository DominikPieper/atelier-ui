# Atelier — Lessons

Patterns and gotchas captured during implementation. When a mistake repeats, add a rule here so it doesn't repeat again.

## Figma plugin API (figma-console MCP)

- **`node.resize(w, h)` flips auto-layout axis sizing to FIXED on both axes.** If you want a frame to auto-size its height (`primaryAxisSizingMode = 'AUTO'`) after setting a width, set the mode *after* calling `.resize()`, not before. Otherwise the frame collapses to the resized height regardless of children. This bit me in Progress body, Combobox panel/wrapper, CodeBlock wrapper/body, and Table inner container — all of which silently clipped or collapsed.
- **Setting `layoutMode` on a frame *after* calling `.resize()` reverts both axes to AUTO.** The frame then shrink-wraps to its children — e.g. a 32×32 circle with a "1" text inside collapses to a narrow pill. After flipping layoutMode, explicitly re-assert `primaryAxisSizingMode` and `counterAxisSizingMode` to `FIXED` and call `.resize()` once more, or set layoutMode first and size last.
- **`primaryAxisAlignItems='SPACE_BETWEEN'` with a single child centers it.** This bit the CodeBlock `no-copy` header (single `typescript` text centered) and every Combobox option row without a checkmark. Use `'MIN'` plus `layoutGrow=1` on the first child to push later items to the end.
- **Moving a SECTION on the page does NOT move its children.** Section children are positioned in page-absolute coordinates. After bumping a section's `.y`, re-apply the same delta to every child (`child.y += deltaY`), or reposition the compSet at `(sec.x + 24, sec.y + 92)` explicitly.
- **Text in a fixed-width container won't wrap unless you set `textAutoResize='HEIGHT'`** — Figma defaults to `WIDTH_AND_HEIGHT` so long strings overflow and get clipped by parent `clipsContent`. Setting HEIGHT then explicitly resizing the text width = content-area width makes it wrap properly.
- **`node.layoutPositioning = 'ABSOLUTE'` requires the node's parent to already have `layoutMode !== 'NONE'`.** Parent the node first (`parent.appendChild(node)`), then set `layoutPositioning`. Setting it on an unparented or NONE-layout child throws.
- **`counterAxisAlignItems` enum is `'MIN' | 'MAX' | 'CENTER' | 'BASELINE'`** — not `'START'`/`'END'`. `START` will throw a validation error.
- **REST-backed Figma tools (screenshots, `figma_get_component_image`) 403 without `FIGMA_ACCESS_TOKEN`.** Use structural inspection via `figma_execute` (read `fills`, `boundVariables`, dimensions) when the REST path is unavailable. The Desktop Bridge channel still works for creation/modification.
- **Node-ids in URLs use `-` instead of `:`** — `parameters.design` links like `figmaNode('420-87')` map to Figma node `420:87`.

## Design-system parity

- **Bind every color in a new Figma design to a UI Tokens variable, never a raw hex** — otherwise Dark mode won't follow. Use `figma.variables.setBoundVariableForPaint(paint, 'color', variable)` and discover variables with `figma.variables.getLocalVariablesAsync()`.
- **Before writing new component CSS, check if an equivalent semantic token already exists** (`--ui-color-on-primary`, `--ui-color-text-on-danger`, etc.). Hard-coding `#fff` or `#000` for "on colored background" bypasses the token layer and breaks theming.
- **Storybook `parameters.design` lives on both the meta and every named story** — meta links to the component set, individual stories link to specific variants. Pattern established by `libs/angular/src/lib/button/llm-button.stories.ts:5-9,38-74`.

## Docs site redesign (2026-05-01 batches)

- **Astro `Icon name={literal}` uses string-literal union autocomplete; data-driven callers (`SECTION_ICONS[key]`, BottomNav `icon` prop) need `IconName | (string & {})` in the prop type or the typecheck explodes** with `ts(2322): Type 'string' is not assignable to type 'IconName'`. Lesson: when extracting a typed icon registry, leave a controlled-escape so consumers driven by data don't need a cast at every call site. `& {}` keeps the literal autocomplete while widening the runtime type to string.
- **`navigator.clipboard.writeText` rejects with `NotAllowedError: Document is not focused` when invoked from devtools / a backgrounded tab.** Programmatic copy-button tests fail in the test surface even when the wiring is correct. Lesson: don't take a backgrounded `await navigator.clipboard.writeText` failure as a real bug; verify by clicking in a focused window. Same caveat applies to programmatic `.focus()` and `:focus-visible` matching — keyboard intent (real Tab key) is the only thing that triggers `:focus-visible`, not `el.focus()`.
- **`@media (prefers-color-scheme: dark)` source swaps via `<picture>` don't react to a JS-set `data-theme` override.** When the topbar theme toggle writes `data-theme="dark"` on `<html>` while the OS prefers light, `<picture>`'s media-source resolution is locked at parse time — images stay light. Lesson: pair the media query with a `MutationObserver` on `<html>`'s `data-theme` attribute and rewrite `<img>.src` from a sibling `data-light-src` cache when the override flips.
- **Astro's scoped `<style>` rewrites class selectors to `.foo[data-astro-cid-XXX]` so cssText scans for bare `.foo:focus-visible` miss the rule.** Verifying focus-visible wiring via DOM stylesheet inspection requires querying the rule by `selectorText` containing the base class, not as a substring of `cssText`. The rule still applies at runtime — just don't trust naïve substring greps.
- **Brand-recurring phrase coverage is case-sensitive.** `rg "single source of truth"` misses sentence-starting `Single source of truth`. When auditing recurring-phrase land-rate, use `rg -i` or check both. Don't double-place a phrase because the first instance is sentence-cased.
- **The Astro dev toolbar + Claude in Chrome dev affordances inject DOM siblings outside `#docs-shell` (`<a id="bottomBar">`, `<astro-dev-toolbar>`).** A site-wide axe-core run flags these as accessibility violations even though they don't ship in production. Lesson: scope axe to `{ include: [['#docs-shell']] }` to filter dev-only injections out of the report — same approach for any future automated a11y CI.
- **Page-hero / section-head / pillar / code-card chrome lives in `landing.jsx` + `landing.css` at `skills/atelier-design/ui_kits/docs-site/`.** Always read those two files when building a new section before writing CSS from scratch — kit specifies exact radius (lg=14), exact stroke (1px), exact ease (`cubic-bezier(0.16, 1, 0.3, 1)`), and exact crosshair-grid mask (`radial-gradient(ellipse 800px 500px at center, #000 30%, transparent 75%)`). Token-driven recreation lands in one batch; freelancing the chrome leaks into a five-batch reconciliation later.
- **Inline `navigator.clipboard.writeText` patterns must keep the success-state visual swap inside the `try` block after `await` resolves.** Earlier index.astro logged `console.error` on failure but still flipped the button to "Copied" — visual state misrepresented reality. Lesson: only flip success after the await; the catch path keeps the button in its original state and writes the failure to an `aria-live` region.
- **`opacity:` reductions silently break dark-mode contrast.** `.docs-nav-link--back { opacity: 0.65 }` on `--ui-color-text-muted` (#94a3b8) sat at 3.78:1 in dark — below WCAG AA 4.5:1. Lesson: any text with `opacity < 0.85` needs an explicit contrast pass against both light + dark surfaces. Prefer dropping opacity in favor of a real muted token rather than blending an opaque color over a dark background.
- **Astro `<style>` blocks need explicit `<style>` import on each consumer; primitives that ship their own scoped `<style>` block have those styles hashed per-instance.** When extracting a primitive (CodeCard, Pillar, CompCard), keep the `<style>` block colocated rather than hoisting to global.css if you want isolation; hoist when the chrome is shared and you want a single source. The MCP card was extracted into CodeCard with isolation; pillars went to global.css for cross-page reuse.
- **`is:inline` scripts in `<body>` re-execute on every ClientRouter swap, and `astro:page-load` fires on the initial load too.** The pattern `initPage(); document.addEventListener('astro:page-load', initPage);` therefore double-binds on first paint (direct call + event) — symptom: mobile menu button click toggles open+close immediately, looks dead. Listeners then keep stacking on later navs. Lesson: guard per-element with a `dataset.bound_<event>` flag inside a `bindOnce` helper, and guard doc/window-level listeners (`astro:page-load`, global `scroll`) with a `window.__atelier*Bound` flag. Fixed in `docs/src/layouts/BaseLayout.astro:466-602`.

## Gate redesign — behavior markers → typed covers() (2026-05-30)

- **A drift gate that greps a hand-written comment proves a *string exists*, not that the thing is true.** The old `check:behavior` grepped `// @behavior <id>` in the joined spec files — so a marker above the wrong `it()`, in dead code, or mistyped silently passed/failed. Replacement: a generated typed map (`behaviors.generated.ts`) + a `covers('<subject>','<id>')(title, fn)` helper that returns Vitest's `it`. The id is `BehaviorId<S>` so a typo is a **compile error**, and the gate AST-scans `covers()` *call expressions* (still static, never runs tests). Lesson: when a "forgettable annotation" gate is the complaint, move the annotation from a comment to a typed callsite and read it via AST, not regex.
- **A generated `.ts` that emits object keys must quote any key that isn't a valid JS identifier.** `code-block`/`radio-group` subjects produced `code-block: [...]` → `TS1005 ',' expected`. The JSON manifest read fine (JSON keys are strings) so it only surfaced at `tsc`. Quote with `/^[A-Za-z_$][\w$]*$/.test(key) ? key : "'" + key + "'"`. Always `tsc` a freshly generated `.ts`; don't trust that valid JSON round-trips to valid TS.
- **`tsc -p libs/<fw>/tsconfig.spec.json` is NOT clean on main** — pre-existing `toHaveBeenCalledOnce` matcher-type errors + a few story type mismatches. Specs run via vitest/esbuild (no typecheck), so the repo tolerates them. Lesson: don't use "spec typecheck is clean" as a migration baseline; to prove a new type guarantee, inject the bad value and grep for *that specific* TS2345 line rather than expecting zero errors.
- **Workflow tool: the `args` global arrived `undefined`** (`items.map is not a function`) even when passed as a JSON array in the tool call. Fix that always works: inline the work-list as a `const items = [...]` literal in the script (edit the persisted script file, re-invoke with `scriptPath`) instead of depending on `args` injection. Reserve `args` for values you can tolerate being absent.
- **Workflow scripts use top-level `phase()/agent()/parallel()` + a global `args`** — NOT an `export default async function({...})` shape with injected `fs`/`glob`. The script has no filesystem access, so compute file lists with Bash *before* launching and pass them in (inlined).

## Gates that claim coverage they don't have (2026-08-26)

- **Never justify a gate's scope with what *another* gate is assumed to guarantee — go read that gate.** `check-geometry.mjs` measured React only, on the stated grounds that "check:sync guarantees the CSS is mirrored". `check:sync` compares component-directory presence and story presence and has never read a byte of CSS. The invented guarantee hid a 20px defect: Angular's `<atl-button>` is a custom element (`content-box` by default), so `size=md` rendered 60px against a 40px token while the gate reported the library green. Lesson: when writing "X guarantees Y" in a comment, open X first. If the guarantee isn't there, either measure it yourself or say the coverage is partial.
- **A test fixture must not supply what production is missing.** The same gate injected `* { box-sizing: border-box }` "deliberately, named" — which handed the components the very reset consumers don't have, so it measured a best case nobody ships. Lesson: a fixture's job is to reproduce the consumer's environment, not a comfortable one. If the library needs a precondition, ship the precondition instead of granting it in the harness.
- **Form controls are border-box in the UA stylesheet; custom elements are not.** `<button>`/`<input>` are immune to a missing reset, `<atl-button>`/`<div>` are not. So "does this library need a reset?" has a different answer per framework for the *same component*, and measuring one framework proves nothing about the others. Measured delta for React's button: exactly 0.
- **A per-framework claim needs a per-framework measurement.** ADR-0041 said buttons "compute exactly 32 / 40 / 48". True in React and Vue, false in Angular by 14–25px. The three adapters share a spec, not a box model.

## Counting shapes, not call sites (2026-08-26)

- **When a finding says "X is not an icon", check what the icon component actually renders before designing the fix.** AtlInput's invalid indicator was a CSS `content: '✕'`; AtlIcon's `danger` was the Unicode `'✕'` — the same character. The real problem was not the pseudo-element but that the library had no icon strategy: AtlIcon was a glyph map with zero internal consumers while 11 components drew their own svgs. Lesson: normalise and *count the distinct shapes* per concept. `close` existed 4 ways, `check` 3, `chevron-down` 2 — invisible when counting files, obvious when counting geometry.
- **Render a contact sheet of any generated set and look at it.** The first draft of the icon geometry gave `success` and `check` the same path — the exact duplication the whole change was removing. No test would have caught it; one screenshot did.
- **`git checkout -- <file>` after a negative test throws away uncommitted work in that file.** Reverting a deliberately-broken file wiped an unrelated uncommitted edit in `libs/spec/src/index.ts` from earlier in the same session. Lesson: for negative tests, `cp` the file to a scratch path and restore from there, or commit first.
- **Angular's AtlIcon styles itself via `:host` and carries no `atl-icon` class**, so cross-framework CSS selectors are not interchangeable: React's `.atl-icon.icon` is Angular's `atl-icon.icon`. A rendered-DOM probe (`outerHTML`) settled it in one run after a class-based assertion failed.
- **Angular Testing Library instantiates the TestBed on the first `render()`** — a second `render()` in the same `it()` throws `Cannot configure the test module when the test module has already been instantiated`. Split the test.

## Measure the population before choosing the policy (2026-08-26)

- **"There are literals with no token" is not actionable until you count them by kind.** 190 literals across the component stylesheets sounded like a migration; grouped, it was 116 one-off component dimensions, 17 viewport units no token can hold, and **13 that duplicated a token which already existed**. Only the 13 were objectively wrong. Tokenising the 116 would have produced ~100 single-use tokens — the rule of three violated in token form.
- **A value-equality scan needs property→token-family awareness or the number is noise.** Matching any token by value claims 94 hits and cheerfully suggests binding `margin: 0` to `--ui-z-base`. Per-family comparison gives 13 real ones. Report the family-aware number, never the naive one.
- **A gate whose roster is built from token references cannot see a component that hardcodes the value.** `check:geometry` measured 12 boxes and missed AtlTab (41px) and AtlCodeBlock's header (43px) because they wrote `2.5rem` instead of `var(--ui-control-height-md)`. Binding the literals put eight more components on the roster and took it to 36 measurements. Lesson: when a gate discovers its subjects by looking for a token, ask what a bypass looks like — that is where the defect will be.
- **I re-broke my own uncommitted work with `git checkout --` a second time in one session**, on a file I had deliberately corrupted for a negative test. Writing the lesson down was not enough; the fix is mechanical — `cp` to the scratchpad and restore from there, never `git checkout` while anything is uncommitted in that file.
- **Deriving a height from a label's font metrics only moves the guess.** The code-block header's padding was rewritten as `calc()` over the mono label's size and still rendered 43.59px. The honest fix was `padding-block: 0` and letting `min-height` decide on a centred flex row — the label's line box is not the header's business.

## Local green, CI red — and the check that could not see it (2026-08-26)

- **A gate that measures rendered output is only as reproducible as the fonts on the machine.** `check:geometry` passed locally and failed in CI: AtlSelect used `min-height` with authored padding and no line-height, so its box was 40.4px with Instrument Sans installed and 40.7px with the runner's fallback — 40 vs 41 after rounding. The fix was not to pin the environment but to remove the dependency: state the line-height, derive the padding.
- **`min-height` + authored block padding is an anti-pattern**: it states a height and delivers the content's height. Where they agree it is luck, and luck is machine-specific. Three more controls (tab, menu item, code-block header) were stable only because their content happened to fit.
- **My first discriminator did not work, and the negative test is what proved it.** Measuring each box twice with different font families found nothing, because two locally available fallback faces differ by less than the 0.5px tolerance. Lesson: after adding a check, break the thing it is supposed to catch and confirm it fails. A check that cannot detect its own failure class reads as coverage while providing none — delete it rather than keep it.
- **The probe that works perturbs the property, not the environment**: `* { line-height: 3 }` with no `!important` lands on every element that does not state its own line-height and loses to every element that does. If the box moves, its height is inherited. Same trick applies to any "is this value stated or inherited?" question.

## The constraint that depends on the consumer (2026-08-26)

- **"Apply it on the app shell" is a constraint a component cannot keep.** `--ui-font-family`'s manifest said not to respecify per component, so 25 roots that did looked like violations. Measuring inside an app whose own font was Georgia inverted it: Card, Dialog, Chat, Skeleton and AvatarGroup rendered *Georgia* while Button and Input rendered Instrument Sans — the missing declarations were the defect, not the present ones. Lesson: before cleaning up something a written rule calls a violation, render the two states side by side and see which one is wrong.
- **Measure the property, not the sample.** A nine-component fixture said five were wrong; running every component root through the same fixture, per framework (Angular via host-selector rewriting), gave the real list and caught five more in Angular alone.
- **`all: unset` silently wipes a declaration placed above it in the same rule.** The dialog's new `font-family` did nothing until it moved below the reset. Any rule with `all: unset` has to restate every inherited property it needs.
- **A "shortest class name = component root" heuristic is wrong** in a flat-named CSS convention: it picked `.atl-combobox-input` over `.atl-combobox` and `.atl-dialog-footer` over `.atl-dialog`, producing four confident false positives. Deciding structurally (one compound selector, no descendant combinator) is correct and needs no name mapping.
- **A declared token layer with zero consumers may be over-designed rather than unfinished.** ADR-0036's eight `--ui-type-*` roles fit 5 of 105 typography rules without changing what renders; 83 rules set a single axis. Adopting the layer means committing to explicit line-heights across ~24 components — a redesign, not a migration. Lesson: measure the fit of an abstraction against the real population before "finishing" its rollout.

## Verifying with a narrower target set than CI runs (2026-08-26)

- **`nx build <project>` is not what CI runs.** CI runs `nx run-many -t build` across every project, which selects the *production* configuration — and `angular:build:production` typechecks templates strictly where the default configuration does not. My local `nx run-many -t build -p react vue angular` reported success while CI failed on template type errors in the same files. Lesson: verify a build with the same command CI uses (`run-many -t build`, all projects, `--skip-nx-cache`), not a subset.
- **A `Record<Union, X>` map that intentionally omits members must be `Partial<Record<Union, X>>`** — and then every read site has to handle `undefined`. Converting AtlAlert/AtlBadge's glyph maps to icon-name maps hit this three ways at once: an implicit-any index (TS7053), a `string` widening in a Vue template (TS2322), and an import colliding with a locally declared union (TS2440). None of them appeared in the dev build.

## The fixture that made its own numbers (2026-08-27)

- **A measurement harness is code, and mine had two bugs that both produced plausible numbers.** Measuring Angular means rewriting `:host` to a tag selector, and I concatenated the component's stylesheet with `atl-icon.css` before rewriting *both* with the component's tag. `:host { display: inline-flex }` from the icon landed on `atl-checkbox`, `atl-radio` and `atl-toggle`, so three roots stopped being blocks and every Angular figure in that run was wrong. It read as Angular being *more* correct than React — the checkbox root measured 40 where React measured 48 — which is exactly the shape of result that does not prompt a second look. Lesson: when one framework disagrees with the other two, suspect the fixture before the framework, and confirm by measuring that one box in isolation.
- **The same bug was latent in the gate.** `check:geometry` hostified per directory, which was correct only while no directory held two components. Adding `atl-option.css` to `select/` would have made it silently wrong. Deriving the tag from the stylesheet name is the fix, and it is the convention the repo already follows.
- **A probe can be too strong for what it is asked to gate.** `* { line-height: 3 }` lands on every element that states nothing, which is right for a control — it owns everything inside it. For a row that hosts content the app supplies (AtlCheckbox and AtlToggle render `children` with no wrapper), passing it would require overriding the app's own text. Rows are gated on inherited leading instead, which is the hazard that actually exists. Lesson: the strictest available check is not automatically the right one; match the perturbation to the failure the box can really have.
- **And it can be too weak in a way a multiplier hides.** `line-height: 3` against 12–16px text is 36–48px, which fits inside a 40–56px row without touching it — so the probe passed a table cell whose line-height I had deliberately deleted. An absolute leading larger than any rung on the ladder has no such blind spot. Lesson: when a perturbation is proportional to the content and the assertion is about a box, check the headroom before trusting a pass.
- **`min-height` is not honoured on `display: table-cell`; `height` acts as a minimum there instead.** Measured: `min-height: 48` gives 18.5px, `height: 48` gives 48px and grows to 88.5px when the content wraps. A written decision that says "min-height everywhere" is right about the semantics and wrong about the property on exactly one display type.
- **A shorthand later in the same rule erases the longhand above it — third occurrence.** `all: unset` took the typeface twice; `font: inherit` took the row's stated line-height. Three is a rule: any longhand a shorthand can reset belongs below it.
- **A specimen that cannot reproduce a number should not print it.** The AtlCheckbox artboard drew its "before" rows from plain divs, which have no native input and therefore no UA margin — 24px drawn under a label saying 26px. Either reproduce the mechanism or set the measured value and say that is what you did.

## A green local run that proved nothing (2026-08-27)

- **A required `peerDependency` is an install instruction, not a compatibility note.** npm installs it for you and resolves the range to whatever is newest. `@atelier-ui/create-workspace` declared `@nx/angular: ">=22.0.0"` while its own generator ran `ensurePackage('@nx/angular', NX_VERSION)` two lines in — so npm installed 23.1.2 into a workspace pinned to nx 23.1.1 before the line that would have got it right ever ran. Where a package installs a dependency itself, a required peer is a second installer with worse information; mark it optional. Verified both ways in clean directories: required → 23.1.2 installed, optional → nothing installed.
- **"Green locally, red in CI" is a claim to test, not a conclusion to draw.** The local e2e passed *with the identical skewed pair installed* — nx 23.1.1 and @nx/eslint 23.1.2 in the same generated workspace — because that workspace's `nx.json` had no `plugins` array, so nothing ever `require`d the plugin that throws. The environment was not the difference; what loaded was.
- **Read the failure's ordering before choosing where to fix it.** My first fix rewrote every `@nx/*` entry in the generated `package.json` to `NX_VERSION`. The CI log says the throw happens *during* preset application — before any install task could honour that rewrite. The log said so in the two lines around the error, which I had already read.
- **Check the publish timestamp when a job goes red on an unrelated diff.** `nx@23.1.2` was published 17 minutes before the run. That does not excuse the failure — the range that let it in was ours — but it is the fastest way to tell "my diff did this" from "my diff was merely present".

## What a stale finding costs, and two half-measures I caught myself making (2026-08-27)

- **One noticed divergence had four unnoticed ones under it.** Two artboards said "invalid is carried by colour alone". Auditing all four form fields across three frameworks found that plus: `aria-describedby` in 5 of 12 combinations, the error message rendering under three different rules, the live region assertive in two places and polite in ten, and the select's chevron being a text character. Lesson: when a sheet reports one inconsistency in a family, audit the whole family mechanically before fixing the one — the reported defect is a sample, not the population.
- **A gate I wrote was wrong twice, and both times the data said so, not the run.** `[BOOL-CLAIM]` first only asked "does that interface have that field", which passes AtlRadio — whose master claims `AtlFormFieldSpec.invalid` while `AtlRadioSpec` extends nothing. `[BOOL-MISSING]` first assumed a flag can only be a Boolean, and reported AtlInput's `invalid` as missing when it is a value of the `state` axis. A new check's first green run proves nothing; read its output against the source it describes.
- **Splitting a bucket can be worth more than filling it.** Lumping AtlTooltip's `position` axis in with AtlBreadcrumbs' `items` axis would have told the reader to delete a real prop: the prop is `atlTooltipPosition`. `[AXIS-NAME]` and `[AXIS-NOT-A-PROP]` are different repairs.
- **An exemption list is where a rule goes to die.** I wrote `«` and `»` into `[TEXT-GLYPH]`'s exempt set as French and German quotation marks — true, and it let six live first/last-page arrows through in the same change that closed the rule. A character is exempt because of the job it does on the page, not a job it can do elsewhere.
- **Two half-measures, caught by re-reading my own argument.** I first wrote a note file *beside* two artboards that still said "open", and I first put a one-declaration correction in a *new* stylesheet rather than the shared one every sheet already loads. Both are the pattern I had spent the session removing: a true statement placed next to a false one. Correct the source.
- **A snapshot diff reading `"name": ""` looks exactly like a name being lost.** The pagination a11y baselines changed when glyphs became vectors. All eight buttons kept the names their `aria-label` gives them; only the text-derived names of `list` and `listitem` wrappers changed. Check the interactive elements explicitly before accepting or rejecting such a diff.
- **A finding can be wrong in the direction that makes it look small.** "There is no Figma master for AtlIcon" would have been answered by building one. What was there was worse: 21 icon components each holding a single Unicode TEXT glyph on a 32×19 frame — a complete-looking library made of the exact defect three earlier ADRs had each removed from one layer of the code.

## Phase 3, first stage: trusting my own new check over the gate that already worked (2026-08-27)

- **I renamed a correct axis because my new check compared the wrong thing.** `[AXIS-NAME]` said AtlTooltip's axis `position` should be `atlTooltipPosition`, because that is the spec *field*. The file's convention derives an axis name from the spec *union* — `AtlButtonVariant` gives `variant`, `AtlTooltipPosition` gives `position` — and the existing `[NAME]` rule enforces exactly that. My rename tripped it as a **blocker**. Lesson: when a new check disagrees with an old one in the same file, the old one has been running against real data for longer; find which convention each encodes before acting on either.
- **`node.remove()` on a COMPONENT_SET with children did nothing and reported nothing.** I moved a variant out, called `remove()` on the set, got no error, and carried on — leaving two nodes with the same name and every drawing duplicated. Worse than the starting state. Removing the children first, then the set, worked. Lesson: after a structural edit in Figma, read the node back; the API is not uniformly loud about refusals.
- **A hardcoded list of flag names is a hardcoded blind spot.** `[BOOL-MISSING]` checked `disabled, invalid, required, readonly, loading` and so never asked about `AtlPaginationSpec.showFirstLast`, `AtlTableSpec.stickyHeader`, `AtlAlertSpec.dismissible`, `AtlSkeletonSpec.animated` — nine more masters. Deriving flags from the spec **types** turned 3 findings into 14. A flag is a flag because of its type, not its name.
- **Then that check over-reported, and the fix was to read what the masters already said.** `AtlToggleSpec.checked` is expressed as the axis `selection` = off|on, and the master's own description says `- Variant \`selection\`: maps to AtlToggleSpec.checked`. Parsing that line resolved it. A flag can be expressed as a Boolean, as an axis value, or as an axis mapped to it in prose — accept all three or the gate sends the reader to add a property that contradicts what is there.
- **An exemption belongs in the artefact, not in the gate.** For a flag whose false value renders nothing (`open` on a dialog) the gate now accepts `- Boolean \`open\`: not modelled — <reason>\` in the master's description. A list inside the script would be an exemption nobody reading the master can see — the same mistake as the `«»` guillemets.
- **The snapshot's master list is hardcoded node IDs.** Collapsing two COMPONENT_SETs to plain COMPONENTs changed their ids and broke the snapshot silently — it kept reading the deleted sets. Structural changes in Figma have a repo-side cost that nothing announces.

## The question before the task (2026-08-27)

- **Asking what the tool can express changed the whole work order.** Before drawing nine states I asked what a Figma Boolean binds to. Answer: a layer's `visible`, nothing else. So a colour-only state cannot be a Boolean, and my gate had been telling the reader to add ones that could not work. Two minutes of reading existing bindings was worth more than the nine drawings would have been.
- **The same read found the inverse defect, four times larger.** Nineteen declared Booleans reference nothing — all five on AtlTable — so switching them changes nothing. `[BOOL-MISSING]` had been reporting absence while the common case was inertness. Whenever a gate reports "X is missing", check whether X exists and is broken; those are different repairs and the second is easier to overlook because the API surface looks complete.
- **A gate built on prose measures the writing, not the thing.** ADR-0056 parsed Boolean properties out of the masters' descriptions because that was the only place they existed. The fix was to make them exist: one probe round trip in the snapshot, and four masters moved from "declares none" to "declares an inert one". If a check has to read prose, treat that as a gap in the capture layer rather than as the design.
- **And it found the icon defect a fifth time.** Forty-two pictograms are TEXT characters inside fifteen masters — after ADR-0046 removed them from CSS, 0050 from TypeScript, 0055 from templates, 0057 from the Icons page. Each of the four fixes was complete for its layer and the defect simply lived elsewhere. Lesson: when a defect has a shape ("a character standing in for a drawing"), enumerate every place that shape can hide before declaring the class closed.

## Two claims I asserted that the file had already disproved (2026-08-27, later)

- **"A colour state cannot be a Boolean" — wrong, and three masters already did it.** I read the binding rule (a Boolean binds only to a layer's `visible`), concluded a colour difference could not be one, and wrote it into an ADR. AtlSelect, AtlCombobox and AtlCheckbox each carry an `_invalid-border` rectangle bound to their `invalid` Boolean: an overlay that paints the new colour turns any colour state into a visibility state. Reading one more thing — what the existing bindings *are*, not just what the API allows — would have caught it. Lesson: after deriving a limitation from an API, look for the workaround in the artefact before writing the limitation down.
- **Deleting a property because its documentation was wrong.** `[BOOL-CLAIM]` correctly reported that AtlRadio's `invalid` Boolean claimed `AtlFormFieldSpec.invalid` while `AtlRadioSpec` extends nothing. I deleted the property — and orphaned the `_invalid-border` layer it was driving. An invalid radio *is* a rendered state: `atl-radio.tsx` computes `ctx.invalid && 'is-invalid'` from the group's context. The mapping was wrong; the property was doing real work. Restored, rebound, and the description now says *inherited from* `AtlRadioGroupSpec.invalid`, which the gate checks as its own claim form. Lesson: a false claim about a thing is a reason to correct the claim. Check what the thing does before removing it.
- **Replacing a glyph with an icon needs four properties carried, not two.** Position and size were not enough: the master's auto-layout ignored my x/y because I had not copied `layoutPositioning`, so the first chevron landed at the top-left corner. Carry `layoutPositioning`, constraints, and `componentPropertyReferences` — a glyph may be the layer a Boolean toggles.
- **`mainComponent` returns nothing under `documentAccess: dynamic-page`.** `getMainComponentAsync()` is the form that resolves. The synchronous getter fails silently, so a probe built on it reports an empty set rather than an error — and an empty set reads exactly like "there are none".

## Migrating 120 nodes: the number, and the three that were not the job (2026-08-27)

- **The reported count was the deduplicated one.** `[MASTER-GLYPH]` said 42 pictograms; the file had **120** nodes, because every variant carries its own copy and my probe deduped by layer+characters. A count that feeds a work estimate has to say which it is.
- **Carry the bound Variable, not the resolved colour.** Every glyph already had a colour Variable bound (`color/success-text`, `color/text-muted`, …). Reading `paint.boundVariables.color` and re-binding it on the replacement kept the token discipline through the swap; copying the resolved paint would have quietly converted 83 bound colours into raw ones — which the token-binding half of the same gate would then have reported.
- **Three of the fifteen masters were not this job, and finding that out was the job.** The `⟳` spinners are a CSS ring — `border: 2px solid currentColor` with a transparent top edge — so an icon instance would have been wrong; an ellipse with a 270° arc is right. AtlCheckbox's tick is `::after` with two borders rotated 45°, a different drawing from the `check` icon. AtlChat's `–` is a minimise control the component does not have at all. Substituting an icon in any of the three would have made Figma agree with an idea of the code rather than with the code.
- **`currentColor` has to be read from the neighbour.** The spinner takes the colour of the text beside it, which differs per variant — white on a primary button, teal on an outline one. Carrying the glyph's own grey would have been faithful to the glyph and wrong about the component.

## Nineteen properties, and twelve of them had nothing to bind (2026-08-27)

- **`required` renders nothing, in five components.** I expected an asterisk. The code passes `required` to the DOM as the HTML attribute and stops: no class, no CSS rule, no mark. The asterisk I had been drawing in the artboards came from the label text *I* wrote. So five of the nineteen "unbound Booleans" were unbound because there was nothing to bind — and a Figma property for them is only honest as a stated exemption.
- **Four of AtlTable's five belonged to its children.** `sortable` is `AtlThSpec`, `selectable` is `AtlTrSpec`, `empty` is `AtlTbodySpec`; `error` is in no spec at all. The container declared them, nothing could reference them, and that is exactly the "container claims its children's states" shape from ADR-0056 — showing up as inertness rather than as a wrong axis. Two findings that looked unrelated were one.
- **I wrote "owed, not exempt" using the form the gate reads as exempt.** The stated-unbound line excused `stickyHeader` while its own text said it was owed. Caught by re-reading the tally, not by the gate — the gate did exactly what I told it. When a check accepts a written exemption, the writing IS the switch: never use its wording to say something is not exempt.
- **Two properties map to nothing at all** — AtlButton `hasIcon` and AtlTable `error`. Neither appears in any spec, CSS rule or render condition. A master can invent API as easily as it can omit it, and only the type-derived comparison catches the invented kind.

## Binding seven states: four wrong guesses, each caught by reading the tree (2026-08-27)

- **AtlToast's dismiss slot had been mislabelled by my own glyph pass.** Every variant has its status icon at x=0 and a second icon at the far right; my STATUS_SETS rule mapped that second one to `danger`, so a `default` toast showed a danger mark. The layer's position, not the master's category, was the tell.
- **AtlPagination has no first/last control at all** — it draws `‹ Prev`, page numbers and `Next ›`. I bound `showFirstLast` to the first and last PAGE NUMBER buttons, which would hide page 1 and page 10. Reverted. Before binding a property to "the outermost thing that looks right", read what the layer actually is.
- **`‹ Prev` slipped through `[MASTER-GLYPH]`** because the check tested whether the whole trimmed string was a pictogram. A pictogram embedded in prose never matches a length test. Two live instances hid there, and the same string carried a second divergence: the code renders those buttons icon-only with an `aria-label`, so the visible word was the master's invention.
- **AtlRadioGroup's radio circle is a FRAME, not an ELLIPSE**, so my overlay loop created nothing and reported `overlays: 0` — a silent no-op that looked like success until the gate still flagged the property. A creation count of zero deserves the same suspicion as an empty result set.
- **A new layer inherits none of the parent's token bindings.** Copying `v.cornerRadius` gave the shimmer a raw 8 and tripped the token gate as a CRITICAL. Copy the *binding* (`boundVariables.topLeftRadius`), not the resolved number — and where the parent has no binding either, do not invent one.

## The typeface: three fonts, none of them ours (2026-08-27)

- **A one-line preparatory read found a defect bigger than the task.** I only wanted the font to build ten child masters in. It came back Inter, against `--ui-font-family: Instrument Sans` from ADR-0035. Reading the *existing* state before adding to it is what caught it — had I assumed the file was right and copied its font, the ten new masters would have deepened the divergence instead of exposing it.
- **A gate whose name matches the defect can still not cover it.** `check:typeface` was green throughout. It reads the CSS: the *library* states its typeface correctly. Nothing read the transfer *target*. When a rule spans a boundary, ask which side the gate stands on — the name will not tell you.
- **1600 `await`s inside a loop is what timed out, not the work.** The first sweep died at the 5s limit; hoisting `loadFontAsync` out of the loop did the same 806 nodes in 309ms. `figma_execute` also takes a `timeout` param, which the snapshot script already used at 25000 and my interactive calls did not.
- **Re-tally after a mutation, never trust the change count.** The sweep reported "fixed 18, failed 0" and the file still held 9 Inter nodes. They were in instances of an **orphaned** main component — one Figma keeps alive because an instance references it, unreachable by `findAll`, and thus skipped by every sweep. Two Inventory tiles had drawn pre-fix geometry for months. A count of writes is not a count of effects.
- **The captions became lies the instant the sweep ran.** Nineteen specimen rows each said "Montserrat Regular" beneath text that was now Instrument Sans. They had been true when typed. Any hand-written fact *about* a generated thing is a fact with no gate: derive it from its subject, or expect it to rot silently.
- **Fixing the family exposed four more divergences in the same component.** Restoring mono to AtlCodeBlock made visible that its leading was `AUTO` + a 4px gap (near-right by accident), its header 36px against a 40px token with block padding a row recipe forbids, and its gutter missing the `border-right` and `min-width` the CSS draws. One correct change is a good place to look for the next one.
- **I set padding as raw numbers and tripped my own token gate.** `paddingLeft = 16` instead of `setBoundVariable('paddingLeft', spacing/4)` — the same lesson as the raw `cornerRadius` one commit earlier, in the same session. Writing a number into Figma is never the finished move when a variable for it exists.
- **Prove the gate can fail.** I injected all five defect shapes into the snapshot (foreign family, missing role, wrong size, wrong family, stale style) and confirmed each blocker before restoring. A gate written and only ever seen green is untested code in the position of most trust.
