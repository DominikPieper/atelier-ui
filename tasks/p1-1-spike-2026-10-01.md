# P1.1 spike — can React/Vue CSS be generated from Angular CSS?

Date: 2026-10-01. Throwaway spike; nothing under `libs/` was touched. Input: `tasks/p1-css-inventory-2026-10-01.md`.
Question: is "Angular `:host` CSS canonical, React/Vue generated" (ADR option A) cheap enough, or does the
per-component rule table grow so much that renaming classes first (B/C-shaped convergence) is cheaper?

Generator and config (re-runnable: `node gen.js [dir ...]`; `NODOM=1` drops the DOM escape hatches; `FORCEPREFIX=1`
applies the prefix-everywhere policy):
`/private/tmp/claude-501/-Users-dominikpieper-Projects-atelier/56932b2a-5aee-437a-b1f9-6f468df65ebb/scratchpad/p1-spike/`
(`gen.js` 208 lines, `config.js` 30 lines, plus `renames2.js`, `leaks.js`, `victims.js`, `prefixdiff.js`, `sideeffects.js`;
`out/<dir>.css` generated files, `out/<dir>.diff` residuals).

## Answer in one paragraph

Yes, the transform works and its config stays small: **23 of 29 components are byte-equal to today's React CSS (and to
Vue's, identically) ignoring comments**, with 32 config entries in total across 15 components (14 components need none).
27 of the 32 entries are accidental naming or policy drift, only 5 are inherent. The rename-first alternative is cheap
(about 14 class-bearing template lines, 4 components) and removes 13 of the entries, but it does not remove the DOM
tail (select, tooltip), so renaming first is a preparation step for A, not a replacement for it.
**Recommendation: A, preceded by a small rename pass.**

## Method

1. Generator `gen.js`: postcss + postcss-selector-parser, input = `libs/angular/src/lib/<dir>/atl-<dir>.css`, output =
   class-rooted CSS, formatted with the repo's Prettier (`resolveConfig` against the React target file).
   Angular comments are carried through verbatim.
2. Comparator: generated vs `libs/react/.../atl-<dir>.css`, both comment-stripped, Prettier-formatted, blank lines dropped,
   string-equal. Also compared against Vue (identical outcome, 23/29 both). Residual = lines of `diff -U0`
   (added + removed). A second, order-insensitive rule-level comparison counts differing rules ("semantic residual").
3. Config grown iteratively against today's React CSS: an entry is added only if no generic rule can produce the target.
   (This is fitting to the current files; it measures what is needed to reproduce today, not what is ideal.)
4. For the six DOM-divergent components the DOM escape hatches (`sel`, `addCss`, `addDecl`, table's tag map) are
   reported separately (`NODOM=1` = residual without them).

## Generic rules (in code, no per-component facts)

| #   | Rule                                                                                                                                                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G0  | Root class = the component's own element selector from `atl-<dir>.ts` (`selector: 'atl-tab-group'` gives `.atl-tab-group`). Derives accordion and tabs for free.                                                                                |
| G1  | The Angular box-sizing preamble `:host, :host *` is replaced by the list derived exactly like `tools/scripts/gen-box-sizing.mjs` (every leading `.atl-*` class of the output), so the preamble costs zero config (it never did: it is derived). |
| G2  | `:host` to root. `:host:hover` etc. keep their suffix.                                                                                                                                                                                          |
| G3  | `:host(X)`: if X starts with an `.atl-*` class or `atl-*` tag it is already a host class and is emitted as is, else `root + X`.                                                                                                                 |
| G4  | `:host(X):host-context(Y)` to `<root>Y X` (strict compound ancestor, e.g. `.atl-card.padding-sm .atl-card-header`).                                                                                                                             |
| G5  | Bare `:host-context(Y) rest` to `Y <root> rest` (`[data-theme='dark'] .atl-drawer-host dialog::backdrop`).                                                                                                                                      |
| G6  | Own-component tag selectors (`atl-chat-header`) to classes of the same name; child-component tags and classes (`atl-icon`, `atl-checkbox`) are foreign and get the descendant prefix. Foreign = matches another component directory.            |
| G7  | Any selector with no own `.atl-*` class gets the descendant prefix `<root> ` (policy `prefix`; `bare` is a per-component legacy switch).                                                                                                        |
| G8  | Directly adjacent rules with the same selector merge (comments in between are ignored). Costs: comment/rule association can shift (chat), declaration order inside the merged rule can differ (accordion).                                      |
| G9  | Keyframes untouched; `@media`/`@starting-style` bodies transformed.                                                                                                                                                                             |

## Config vocabulary (what a per-component entry can be)

`root` (override), `scope: 'bare'` (legacy no-prefix), `scopeSel` (one selector stays bare), `rename`/`hostAlias`
(class rename), `tag` (tag to class or tag), `ctx` (ancestor mapping), `mergeFile` (sibling file with own root),
`inlineStyles` (fold `styles:` from a `.ts`, own root, optional dropHost), and three escape hatches: `sel` (regex rewrite
of a whole selector), `addCss`, `addDecl`. The box-sizing "extra root-list members" entry the brief anticipated is
unnecessary (G1).

## Entry classification

**Inherent (5)** — needed because the frameworks differ, and which disappear only by changing the structure:
table tag `atl-tr` to `tr` (Angular wraps each row in a custom element), tabs inline `styles:` (Angular keeps AtlTab's
styles in the `.ts`; also its `:host` shim has no React counterpart), toast sibling file (Angular has a separate
container component), menu panel rule (CDK overlay vs own panel), drawer wrapper `display: contents`.
Plus the unclosed tail: select and tooltip (about 140 lines of React/Vue-only CSS).

**Accidental (27)** — would disappear if one side changed:

## Generator-only side effects

### 1. Prefixing the ~80 unscoped React/Vue rules

Generating prefix-everywhere (`FORCEPREFIX=1`) turns exactly the 80 global rules (36 distinct leading selectors, 8
components: accordion, avatar, breadcrumbs, button, code-block, dialog, drawer, pagination, progress, stepper, table) into
`.atl-x .name`; after dropping that prefix generated and React/Vue agree rule for rule in every component except the
three DOM/value ones (select, tooltip, avatar/toast one declaration each). Nothing else changes.

Does any component depend on the leak? Checked by grepping class contexts outside the owning component and comparing
declaration sets (CSS-level only, not rendered):

- `.close-btn`: defined globally by **both dialog and drawer** (a live collision), and used by the chat header, which has
  its own scoped rule. The leaked rule sets `margin-left, line-height, background-color, outline, box-shadow` that chat's
  own rules do not. So chat's close button gets those only when dialog or drawer CSS is loaded on the page.
- `.panel`: dialog's global `.panel` reaches drawer's `.panel`; the only property drawer does not set itself is `max-height`.
- `.track`: progress's global `.track` reaches toggle's `.track`; the only property toggle does not set is `overflow`.
- Shared tokens `.is-disabled`, `.is-active`, `.size-*` are always compounded with a root class or another class in the
  rules (no standalone leak).
- No parent component styles a child's internal class from outside (the `docs/` and `apps/` greps found none).

So prefixing is safe in the sense that nothing intentionally depends on it, but it will visibly change three places
that today accidentally depend on another component's stylesheet being present: the chat close button, the drawer panel,
the toggle track. Those are existing latent bugs (they only render as designed when dialog/drawer/progress CSS is also
loaded), and Angular's Emulated encapsulation already renders them the isolated way. **Not verified in a browser.**

### 2. `:host-context` semantics (17 occurrences)

Angular matches any ancestor with the class; the generated form requires an ancestor carrying the root class and the
modifier. These differ only if a non-Atelier ancestor carries `.padding-*` or `.variant-*`. Greps over `docs/src`, `apps/`
and `libs/*/src` found no such use. Card stories render cards as siblings, never nested (Angular, React, Vue story files
checked); accordion stories have no nested groups. So no story exercises the difference; the stricter compound form is
what React/Vue use today and what the generator emits. The data-theme drawer rule is an attribute on `html`/wrapper and
behaves identically. Nested cards would behave the same in both forms (both match the outer ancestor).

### 3. Two further things the generator surfaced

- **One Angular stylesheet serves up to 7 components** (chat 7, card 4, dialog 4, drawer 4, table 6, accordion/avatar/breadcrumbs 2).
  Emulated scoping makes a bare `.title` mean "inside this component's own template"; the generator can only say "inside the
  primary root", which is broader, and for avatar's `.overflow-badge` (belongs to the group component) it is the wrong
  root (a `scopeSel` entry pins it to bare). `:host` in a shared file also means every host, but the generator maps it to
  one root (avatar group font-family).
- **Angular comments leak Angular idioms.** Carried-through comments contain `:host`/`<atl-…>` wording in 3 files
  (avatar, card, table). And 26 of 305 React comments are not identical to the Angular comment today (comment drift:
  avatar 2, breadcrumbs 2, chat 2, select 4, table 2, toast 3, tooltip 5, others 1), so generating them removes the drift
  but needs those 3 comments reworded to be framework-neutral.

## Recommendation: A, after a rename pass

Pick **A** (Angular `:host` CSS canonical, React/Vue generated, committed with a `--check` gate in the style of
`gen-box-sizing.mjs`). Reasons:

1. The evidence says the transform is nearly generic: 9 generic rules, 5 inherent entries, and 21 of the 23 non-DOM
   components reproduce today's React/Vue exactly (the other 2 by one Angular declaration each).
2. It does not touch the authoring model of the framework this repo optimises for (Angular is the workshop framework;
   React/Vue are kept in sync infrastructure). B would change Angular's encapsulation across 31 files, with three
   components already `ViewEncapsulation.None` as precedent but 28 relying on Emulated; C needs B's Angular change anyway
   (a shared file cannot contain `:host`), plus a new package.
3. It fixes the existing 80-rule global leak by construction and removes comment and drift (Vue and React stay equal by
   being the same output).

**Strongest argument against A.** The transform is an approximation of Emulated scoping, not an equivalence: one Angular
stylesheet covers several components, so "bare selector means this component's template" and `:host` become "under the
primary root", which can be too broad or the wrong root, and the 100% text equality measured here says nothing about
pixels. And the DOM tail never goes away: select (89 lines) and tooltip (51) are not closable by config, so A leaves
about 140 lines of hand-kept React/Vue CSS (or a config that is mostly raw CSS, which is just a second source with extra
steps). B or C would give one literal file and no transform to trust, at the price of rewriting Angular's CSS once.
If React and Vue are really frozen "not planned" targets, the cheapest option of all is to keep today's hand copies and
only gate drift; A is worth it only if keeping them in sync is meant to continue.

## Verified vs inferred

**Verified (ran):**

- Generator output vs React and Vue CSS at the current HEAD, comment-stripped, Prettier-formatted: 23/29 byte-equal on both;
  every residual listed above comes from the `out/*.diff` files.
- The 80 unscoped rules, the shared-token collisions (`close-btn`, `is-disabled`, `is-active`, `size-*`) and the property
  differences of the three leaks (set differences between rule bodies).
- `:host-context` census and the story searches (no nested cards or accordion groups; no foreign ancestors with those classes).
- The existing preamble generator's rule (`gen-box-sizing.mjs`) is reproduced by G1: no preamble differences in any component.

**Inferred (not run):**

- That identical CSS text means identical rendering (no browser, no `storybook-test`, no `check:*` gates were run against the
  generated files).
- That the three leak-dependent spots (chat close button, drawer panel, toggle track) actually change visually; only the
  declaration-set differences were computed.
- Rename costs: grep heuristic on class-bearing lines; concatenated class names (e.g. React/Vue combobox option classes) are
  undercounted. References in `docs/`, `tools/` and parity snapshots to the old class names are not in the table (a quick file-level grep
  found hits for generic names like `.panel`, `.option`, `.list`), so the real rename needs a targeted pass.
- Effort figures for P1.2-P1.4 are rough estimates from the prototype size.
- That `display: contents` on the React drawer wrapper has no other cause, and that the Vue drawer is visibly broken (carried
  from the inventory, not re-checked).
