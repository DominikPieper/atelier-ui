## No effect observed

- `meta.argTypes` (`description`, `options`, `control`): nowhere in list/show/show-story, text or JSON.
- `parameters.docs.description.component` / `.story`: nowhere.
- `play` function: nothing of it (body, comment, assertion text).
- Tags `!dev`, `!test`, `autodocs` on meta or story; `!manifest` on a **story** (still listed and rendered with code).
- `meta.subcomponents` (second component's inputs/JSDoc absent).
- JSDoc placed between `@Component(...)` and `export class` (only above the decorator works).
- Reordering exports does not change stories listing order but does change which three show code in `docs show`.

## Surprises

1. **Text mode truncates, JSON mode does not.** `docs show` prints code for only the first 3 stories (export order) and puts the rest under `### Other Stories`; `docs list` cuts descriptions at 90 chars + `...`. Anyone measuring with `--json` sees neither. Code for later stories is still reachable via `show-story <storyId>`.
2. Class JSDoc works only **above** the `@Component` decorator; below it silently nothing (cost me a false "no effect" first).
3. `meta.title` drives the **id** (and thereby every story id) but not the displayed name; the name is the component class name (or the title-derived id when `component` is missing).
4. Named union aliases are not expanded (`size?: ChipSize`), so an agent cannot see allowed values from `docs show`; only inline unions (`"info" | "warn"`) are readable. `argTypes.options` does not fill the gap.
5. A story JSDoc is the only per-story prose channel that reaches the tools; `parameters.docs.description.story` is ignored. In text mode the story JSDoc appears in `show-story` (under `# <Component> - <Story>`) and in `show`; the component's class JSDoc is printed by `show` but **not** by text `show-story` (JSON show-story has it).
6. `@example` is split off: list gets only the first paragraph, show prints `**Example:**` with a nested/doubled code fence (cosmetically broken fence), JSON puts it in `jsDocTags.example`.
7. Generated snippets add a `(picked)="picked($event)"` handler for outputs on args-only stories, but not when a `render` uses `argsToTemplate`. A `render` template referencing something unprovided yields a `warning` field (JSON only; visible warning text not seen in text output).
8. Text `show-story` with an unknown `storyName` errors with a helpful list of available ids; JSON mode returned the component entry without complaint.
9. A `!manifest` on meta makes the component vanish entirely; on a story it does nothing.

## Not measured / caveats

- Exact truncation boundary of the list description at 90 chars not pinned (89 intact, 91 cut).
- Whether `subcomponents` compiles/renders in a real browser was not checked (docs tools only); the probe file was valid TS by construction but not type-checked.
- Only the CLI passthrough was used; the hosted/MCP HTTP path (`@storybook/mcp`) was not called. Because the CLI text output matched the MCP-formatted shape (`# Components`, `### Other Stories`), it is likely identical, but that equivalence is **inferred**.
- No dev server was started; no `nx`, no browser tests.
- Tag probes 13a: the snap script could not discover an id after the component vanished (Python errors in `probes.log`); the not-found text is captured in the .txt.
